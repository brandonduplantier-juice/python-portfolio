Project Write-up - In Development - Mobile App

UNPHUCKED: Money, Body, and Life

A phone app that takes the mental load out of money, health, and daily routines. Unlaunched, in private beta development. Started November 2026.

How to read the status labels

Built means the code exists. Tested means automated tests passed. Checked on the test server means it was checked against a private hosted test server using made-up data. Verified on a phone means it was run on a physical device. Nothing on this page is claimed as verified on a phone unless it says so.

What it is

UNPHUCKED is a phone app with the tagline "Less thinking. More living." It puts money, body, and daily life in one place: bills and budgets, workouts, water and food, and recurring routines, with a short list of what to do next.

The goal is to remove mental load. It is built for people who are not comfortable with technology: large touch targets, short labels, one-tap actions, and no tutorial needed. It deliberately avoids engagement tricks, punishing streaks, and heavy notifications.

It is unlaunched and in private beta development. It has only ever held made-up test data.

The privacy requirement

The app asks people for the most private information they have: finances, bills, health, sleep, and menstrual-cycle records. My requirement is that I must not be able to read it. Private records are to be encrypted on the user's phone under keys the user controls, with no copy the operator, the hosting company, or the database can read, and no back door.

This is the largest piece of work in the project and it is not finished. The encrypted on-phone storage exists and features are being moved onto it one area at a time, with the phone's results compared against the server's on made-up data before anything is switched over.

I am not describing this as a finished guarantee. It has not had an independent security review, and no real personal data will be accepted until it has.

Engineering problems solved

  • Sign-in protection that cannot be turned against the user. A common defence against password guessing locks the account, which lets a stranger lock someone out on purpose. The app is designed so that someone else's wrong guesses cannot block a phone the account has already used.
  • Offline changes that are safe to send twice. A phone with a bad connection may send the same change more than once. Every change on the server is all-or-nothing and can be repeated without creating duplicates, with tests for replay and for a failure halfway through.
  • A data leak between two accounts on one phone, found in review and fixed. A problem report written by one person and waiting to send could have gone out under another account on the same phone. Each waiting report now records its owner and only sends under that account.
  • A safety rule that depends on the calendar. A rest period after reported pain is counted in days. Travel or a changed phone clock could have shortened it. The account's saved time zone is now the calendar that counts, and when the date cannot be trusted the restriction stays in place.
  • Honest naming. A button is only called Undo if the original data can really be restored. One that recreated a different record was treated as a defect.

How the work is run

  • Every status report separates built, tested, checked on the test server, and verified on a phone. Nothing is called verified on a phone until I report it myself.
  • Merges, deployments, and new app builds need my go-ahead. So does anything that spends money, turns on a paid service, or touches real personal data.
  • The test server only accepts sign-ups from approved addresses and only holds made-up data.
  • Before any change to the test server's database, there is a checklist: confirm the data is made-up, take a backup that can be restored, and rehearse the change first.
  • One-time codes and secrets must never appear in code history, logs, or build records.

Limits

  • Unlaunched. No real users and no real personal data.
  • On-phone verification is still in progress, and there is no iPhone build.
  • The privacy design is partly built and has not been independently reviewed.
  • Bank connection, AI coaching, and paid subscriptions are not active.
  • The test counts on this page are from Nov 18 to 19, 2026.

The code was written by AI coding assistants working under my direction and review. I am describing that plainly because it is how the work was done.
